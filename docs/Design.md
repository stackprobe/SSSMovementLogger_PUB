# ぐうたら日和の設計

## 通知を必要としない記録

設定画面の全削除は確認ダイアログを挟み、記録の開始・停止・受信と同じSemaphoreSlimで直列化します。保存ファイルを削除し、メモリ内の位置履歴・位置取得ログ・移動変化判定も初期化します。記録と通知の設定は維持し、記録の受信登録は解除しません。削除時刻を設定に保存し、それ以前の位置情報が遅延バッチで再び保存されることを防ぎます。表示済みの会話通知も取り消します。

常駐サービス、StartForeground、記録状態の通知、ワーカーのWakeLock・アラームは使用しません。FLPのLocationRequestと明示的なPendingIntentで、位置情報をLocationUpdateReceiverへ配信します。受信側はGoAsyncで保存を終えてからFinishします。受信と開始・停止はSemaphoreSlimで直列化します。

省電力・5分間隔を希望値として登録し、15分のバッチ配信を許容します。実際のバックグラウンド測位頻度はAndroidの制限を受け、数十分以上空くことがあります。バックグラウンド測位には位置情報の「常に許可」が必要です。開始時に許可を確認し、FLPへの登録成功後に記録中フラグを保存します。アプリ起動時・設定画面への復帰時・端末再起動・アプリ更新時は、記録中フラグにかかわらず権限がそろっていれば自動登録します。同一プロセスで登録済みなら重複登録しません。停止ではフラグを無効化し、位置情報の登録を解除します。停止直後は止まったままですが、次のアプリ起動や設定画面への復帰、端末再起動・更新で再び自動開始します。

AppPreferencesの通知フラグがオフなら、通知の発行処理に入りません。オンの場合も、移動状態が変化したときのこもりのセリフだけを通知します。発行と設定変更を同じロックで保護し、オフにした直後に通知が再投稿される競合を防ぎます。設定オフでは既存の会話通知も取り消します。記録開始・停止・失敗などでシステム通知は出しません。

## 端末内の保存

アプリIDはnet.sss.movementlogger。自身のバックアップ対象外領域のpositions.binに保存し、TTTLATLONLoggerのデータは読み込みません。8バイトのヘッダー（専用magicと-1）の後に、UTC ticks・緯度・経度各8バイトの24バイトレコードを追記します。フラッシュ成功後にメモリの件数を更新し、保存エラー時は記録を停止します。期間・件数による削除はしません。

起動時は全件数・最終点と直近3時間分を復元し、履歴全体をメモリには保持しません。終了で残った24バイト未満の末尾断片だけを回復時に切り詰めます。他アプリの形式や破損はファイルを保持して拒否します。

バックグラウンドで遅れて配信された位置も、正しい測位時刻のまま古い順に保存します。未来時刻、不正な座標、模擬位置、同一時刻・逆順の点は除外します。古いという理由だけではバッチ内の測位を捨てません。

## 会話と通知の判定

直近3時間の記録を使い、20分を超える欠測は距離・観測時間に含めません。観測時間が30分に満たなければ材料不足として話します。最後の測位から15分を超えていれば情報が古いことを話します。基準位置から200m未満の揺れを距離に加算せず、100m/s以上のジャンプを除外します。距離の目安は3km以上・500m以上・500m未満の3段階です。

セリフには観測時間、距離、最初と最後の位置の隔たり、欠測時間を反映します。徒歩や本人の行動を断定しません。移動開始の通知は、30分程度の滞在後に200m以上離れた測位が2回続いたとき。停止は、移動後に10分程度位置の変化が小さいとき。20分超の欠測や不自然な飛びでは判定をリセットします。

記録の復元中には通知しません。まとめて受け取った位置の変化は最大1件にまとめ、最後の測位が15分を超えて古い場合は通知しません。

## 画面

基本画面はキャラクター・吹き出し・設定への入口です。吹き出しは薄紫の塗りと枠、濃い紫の文字で表示します。設定画面には記録開始・停止、こもりの通知スイッチ、設定すべき権限だけの短い案内、権限設定ボタン、折りたたみのログを置きます。状態・診断の詳細はログ内だけに表示します。
